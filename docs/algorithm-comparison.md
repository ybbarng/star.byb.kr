# 별자리 Plate Solver 알고리즘 비교

밤하늘 사진에서 별자리를 찾는 blind plate solver의 알고리즘을 네 가지로
구현하고, **같은 합성 데이터**로 비교한 발표용 자료다.

- 측정 데이터(원본): [`benchmark-results.json`](./benchmark-results.json)
- 비교 실행: `npm test src/test/e2e/compare` (콘솔에 표 출력 + JSON 갱신)
- 알고리즘 구현: `src/search/solvers/`

## 왜 이렇게 비교하는가

실제 노이즈가 많은 밤하늘 사진(아파트 창문·가로등이 별로 검출됨)은
astrometry.net 같은 검증된 엔진도 풀기 어렵다. 그래서 **정답을 100% 아는
합성 사진**(카탈로그에서 임의의 하늘 방향·시야각·회전·노이즈로 생성)을
기준으로 각 알고리즘을 채점한다. 노이즈는 4단계로 올린다:

| 레벨     | 위치 흔들림 | 가짜 별       | 별 누락 |
| -------- | ----------- | ------------- | ------- |
| L0 clean | 0           | 0             | 0       |
| L1 약    | 1px         | 진짜 별의 30% | 0       |
| L2 중    | 2px         | 100%          | 10%     |
| L3 강    | 3px         | 200%          | 20%     |

"가짜 별 200%"는 진짜 별보다 가짜 별(창문·가로등)이 2배 많은, 도시 야경에
가까운 상황이다.

## 네 가지 알고리즘

### 1. 원본 (v2.0.0 발표 버전) — `baseline.ts`

- **별 선택**: 밝기 상위 15개
- **매칭**: 4별 quad의 geometric hash → KD-Tree 최근접
- **검증**: 없음. hash 거리가 가장 가까운 후보의 변환을 그대로 사용
- 한계: 검증이 없어 거리 최소 후보가 틀려도 그대로 오답을 낸다

### 2. 개선 (내 알고리즘 + robustness) — `improved.ts`

원본의 quad geometric hashing **패러다임을 그대로 유지**하고 약점만 보강.

- **별 선택**: 화면을 격자로 나눠 균등 분포 (가짜 별이 한곳에 몰려도 진짜 별 확보)
- **매칭**: 동일 (quad hash)
- **검증 신설**: 후보마다 RANSAC으로 변환을 추정하고, 전체 카탈로그로
  inlier 수와 "우연매칭 대비 유의도"를 계산해 **inlier 최다 후보**를 채택.
  유의도가 낮으면 "못 찾음"으로 정직하게 보고

### 3. 최선A — Geometric Voting — `voting.ts` _(미완)_

완전히 다른 패러다임: 단일 패턴으로 답을 정하지 않고, 사진의 모든 삼각형이
별-별 대응에 **투표**해 다수결로 대응을 정한다.

- 현재 0점. 카탈로그 삼각형이 5.5만 개로 형태 충돌이 커서 단순 다수결의
  정답 대응 비율이 낮다. 투표를 RANSAC과 결합하는 개선이 필요(TODO)

### 4. 최선B — Triangle matching — `triangle.ts`

star tracker의 고전 패러다임. quad(4별) 대신 **3별 삼각형**의 스케일·회전
불변 형태로 카탈로그를 검색하고, 찾은 대응을 공용 검증 코어로 정밀화한다.

- 더 적은 별로 동작하며 매우 빠르다

## 비교 결과 (정답/전체, 12방향)

`fovDeg=20`, 1600×1200, 12방향 평균. "오답확신"은 found=true인데 틀린 위험한
경우, "못찾음"은 정직하게 실패를 보고한 경우.

| 알고리즘       | L0 clean      | L1 약             | L2 중              | L3 강              | 평균 시간 |
| -------------- | ------------- | ----------------- | ------------------ | ------------------ | --------- |
| 원본           | 12/12         | 6/12 (오답확신 6) | 1/12 (오답확신 11) | 0/12 (오답확신 12) | ~70ms     |
| **개선**       | 12/12         | **12/12**         | 1/12 (못찾음 8)    | 0/12 (못찾음 6)    | ~260ms    |
| 최선A voting   | 0/12 _(미완)_ | 0/12              | 0/12               | 0/12               | ~2ms      |
| 최선B triangle | 11/12         | 5/12              | 0/12               | 0/12               | **~50ms** |

성공 시 중심 오차는 모두 0.02~0.07°로 매우 정확하다.

## 핵심 통찰 (발표 포인트)

1. **검증의 힘**: 약한 노이즈(L1)에서 원본 6/12 → 개선 12/12. RANSAC + 유의도
   검증을 추가한 것만으로 정답률이 2배가 됐다.
2. **정직함의 차이**: 원본은 검증이 없어 틀린 답을 "확신"한다(L2에서 오답확신
   11). 개선은 못 풀면 "못 찾음"이라 말한다 — 사람-컴퓨터 협업에서 중요한 성질.
3. **속도 vs 정확도**: 삼각형 매칭은 ~50ms로 가장 빠르나 노이즈에 약하다.
   quad+검증(개선)이 정답률은 가장 높다.
4. **다수결의 함정**: voting은 카탈로그 패턴이 많을수록 형태 충돌로 약해진다.
   "존재만 하면 되는" 삼각형 매칭과 대조적이다.
5. **공통 토대**: 네 알고리즘 모두 같은 검증 코어(`solveCandidate`)와 좌표
   유틸(`wcs.ts`)을 공유한다. 매칭 패러다임만 갈아끼워 공정 비교가 된다.
6. **남은 과제(L2/L3)**: 가짜 별이 진짜 별만큼 많아지면 매칭 단계에서 진짜
   별이 상위 후보 밖으로 밀려난다. 검출 단계에서 가짜 별(모양 필터)을 거르면
   개선될 영역이다.

## 합성 밤하늘 생성기 — `src/test/synthetic/`

이 비교의 토대다. 카탈로그(BSC5)에서 광축 방향·시야각·회전·노이즈·시드를
받아, **정답(중심 좌표·FOV·회전)을 정확히 아는** 밤하늘 사진을 무한히 만든다.
시스템과 동일한 gnomonic 투영(`plane.ts`/`wcs.ts`)을 재사용해 규약 불일치가
없다.

이 생성기는 테스트를 넘어 **밤하늘 게임의 엔진**으로 확장할 수 있다. 예:

- 임의 하늘 한 조각을 보여주고 별자리·방위를 맞히는 게임
- 노이즈(광해·구름)를 단계별로 올리는 난이도 시스템
- 정답을 알고 있으므로 자동 채점·힌트 제공

## 향후

- voting을 RANSAC 결합으로 살려 4개 완전 비교
- 검출 단계 강화(모양 필터)로 L2/L3 정답률 향상
- DB binary 포맷으로 별 등급 확장 (더 어두운 별까지 커버)

## 2. 숫자를 다시 재서 맞출 것 (근거가 흔들림)

- **가장 아슬아슬한 사진 10⁻¹⁷·⁷**(기준 장 그림·오차 보정 장): journey 22장은 정밀화 버그 수정 뒤 최저 17.7 → 19.7. 그림의 누각 23.8도 22장(22.5)과 다르고, OpenCV 제거(27장) 뒤 값이 또 바뀌었을 수 있다. 그림의 출처 측정을 다시 재서 journey에 남길 것.
- **누각 노트 L601 "실제 풀이 10⁻²³·⁸, 데모는 식별 별로만 놓아 덜 나온다"**: `ChanceRatioDemo.tsx` 주석과 `candidates-seoul.json`(16.79)을 보면 데모도 원근으로 다듬은 답. 차이 이유는 "마무리 정밀화(별 60개)로 겹친 별이 늘어서"로 보이나 근거 문서 없음.
- **가짜 후보 최고 점수**: 기준 장은 "가짜는 모두 10⁻⁴·³보다 흔하다", 사이판 노트는 "10만 분의 1 수준까지 온다"(옛 journey 18.1).
- **"지금은 14장 모두 사진 전체에서 풀린다"**(별다움 장·막대 노트): journey 17.4 표는 "별다움 + 전체만" 13장. 지금 코드로 확인한 기록이 없다.
- **L802 "V2의 OpenCV도 같은 방법"**: V2 검출은 OpenCV 윤곽(반지름 순 10개). "흐림·빼기는 V2와 같다"로 좁히기.
- **L569 누각 데모 "V2 방식을 그대로 돌려 봤다"**: 데모는 지금 검출 앞쪽 15개 + 지금 DB로 흉내 낸 것 → "흉내 내".
- **L526 "V3는 틀린 답을 낸 적이 없다"**: 실험 설정에서는 틀린 확신이 있었다(journey 16.7, 17.4). "지금 흐름 기준"으로 한정.
- 문서 근거를 못 찾은 것: Astrometry.net 별 8,400만 개(L1362), "정답 3,049등"(L978, 문서는 중간값 3,052), "73mm·24mm 환산"(L1213), 앱 시각 오후 10시(개인 기억).
- 작은 어긋남: 사이판 별 수(화면 8개 / 노트 10개 남짓), 밝은 별 삼각형 4만 8천·4.9만·4만여, 칸마다 다 만들면 55만(문서마다 51.5만~55.3만 → "50만여 개"), 카페 사진 6장(슬라이드) / 8장(/learn/history, 정답 그림 2장 포함), '나머지' 0.58→0.37(문서 합 0.38).
- 카페 이름: 슬라이드는 "별하늘지기 카페", 저장소 기록은 cafe.naver.com/skyguide만. 같은 곳인지 확인.

## 3. 흐름·구성

- **분량**: 노트만 15,945자 → 읽기만 53~57분, 데모·시연 포함 65~75분 추정. 40~50분이면 20분 넘게 줄여야 한다. 3장이 약 22분(13장)으로 가장 길고, 도입 약 14분, 5장 약 7분.
- **3장**
  - 삼각형 이야기가 4장(쓰면 어떨까 / 닮은 가짜 / 보완재 / 화각으로 거르기) → 2장으로 줄이기 제안. 화각 장 노트(764자, 가장 김)의 알리오트·질문 대비 단락은 빼도 메시지가 그대로.
  - 순서: '보완재' 표의 "삼각형 혼자 14장"은 다음 장 '크기로 거르기' 덕분인데 앞에 나온다 → 보완재 장을 뒤로. "quad 혼자 10장"·막대 "고친 quad 5장"·노트 "삼각형만 3장, 같이 6장" 숫자가 세 벌.
  - 시간 순서가 오간다: 별다움 장에서 "지금은 14장 모두"라고 결론 낸 뒤, 다시 "quad를 고쳤더니 5장"으로 돌아간다. 별 고르기 → 모양 맞추기 사이에 전환이 노트 한 줄뿐 → 전환 장이나 머리말.
  - 3장 제목 "사람이 하던 일을 컴퓨터로"는 앞 절반(별 고르기)에만 맞고 뒤 절반(quad 범위·삼각형·화각)은 "맞추는 모양 바꾸기"다.
  - 핵심인 **별다움**이 제목("밝은 순으로 고르면 불빛이 다 차지한다")·막대에 없다. 해법을 제목으로(예: "별은 사방이 고른 하늘 위에 떠 있다"), 124→280을 화면에 크게.
  - 땅 가리기 노트 L895 "6장에서 13장": 6장은 아직 안 나온 숫자 → "자동으로 푸는 사진이 7장 늘었다".
  - "측정 기준부터 만들고"가 L828·L897에 두 번.
  - '실패한 로직 2: 칸마다 고르게 뽑기' 직후 quad 쪽에서 "사진 별을 칸마다 고르게"를 개선점으로 말한다(다른 단계지만 청중은 구별 못함) → 다른 말로 쓰거나 한 줄 설명.
  - quad-reach 노트 끝(L946)이 다음 장 '삼각형을 쓰면 어떨까'의 답을 미리 말한다 → "그럼 별 셋이면?" 정도로.
- **같은 장 되풀이**
  - '남은 일'이 4번이고 마지막(L1490)은 뜻이 다른 V4 할 일 목록 → 제목 "V4에서 할 일".
  - 'V2를 배포하지 못한 이유'가 같은 제목으로 3번 → 뒤 두 장 제목을 바꾸거나 체크를 한 장에 모으기.
  - 샘플 16장 썸네일이 3번(V2 결과, V3 결과, 3장 끝) + 표 + 시연이 "V3가 낫다"를 미리 세 번 → 'V3 결과' 장을 빼거나 3장 끝과 같은 도장(14 + 모름 2)으로.
- **배포 이유 체크**
  - 정확도 체크 근거에 "사람 손 없이 풀기"가 들어가는데, 처음 장에서 "사람이 별을 고쳐야 풀렸다"는 편의성 항목 → 한쪽으로.
  - 용량은 "서버 비용 걱정"으로 제기했는데 닫을 때는 받는 양만 말한다 → 노트에 "정적 파일 0.68MB라 호스팅 비용도 작다" 한 줄.
- **4장**: 하늘 → 시각(berry·zenith)에서 사이판(시각 → 하늘)으로 방향이 뒤집히는데 연결 문장이 없다. 3·4장이 '남은 일' 중 무엇을 위한 것인지 이어 주지 않는다.
- **결말 순서**: 남은 일 완료 → 2022 목표(클라이맥스) → 덤(게임·learn 시연) → 배운 것 + AI → V4 할 일(글 많음) → 주소 하나 → 지금 써 보세요.
  - 클라이맥스 뒤 덤 시연이 흐름을 끊고, AI 장면 뒤 V4 목록이 여운을 깎는다 → 덤은 "별 놀이터도 있습니다"로 넘기거나 V4 앞으로, V4 할 일은 배운 것 앞으로.
  - '이제는 주소 하나'와 '지금 써 보세요'가 star.byb.kr을 연달아 두 번 → 한 장으로(왼쪽 V2 설치 단계, 오른쪽 QR).
  - '되풀이해서 배운 것' 노트 끝 "이번엔 컴퓨터를 가르칠 수 있었다"와 "AI는 저보다 개발을 잘합니다"가 서로 다른 방향 → 하나로 맺기. AI 이야기가 가운데에 한 번도 없어 마지막 장면이 갑작스럽다(3장에 "AI와 같이 시도했다" 한 줄이면 이어짐).
- **도입**: 시작이 제목 → 머리말 → 글 많은 타임라인(화면 261자). 은하수 사진의 "어떤 별들이 찍혔을까요?"를 먼저 두면 첫 장면이 강해진다. 'V2 마지막에 남은 일' 노트의 "기각 → 점수" 설명은 1장에서 데모로 다시 하니 빼도 된다.

  - '샘플 16장에만 맞춘 건 아닐까' 노트 L1086 "이번 장 끝에서 다시" → 카페 사진은 4장 끝 '달' 장.

## 4. 용어

- **판정을 부르는 말이 여럿**: 필연(제목·데모) / 확신(화면 "틀린 확신", "확신까지 0.13초") / 찾았다 / 성공·모름 / 풀림 / 해결된 사진. 화면은 "필연"으로 시작해 설명 없이 "확신"으로 바뀐다 → '모르면 모른다고 하기'에서 "필연 = 우연일 확률 10억 분의 1 아래 = 확신"을 한 번 잇고 이후 "확신"으로.
- **후보를 만든 별 3~4개**: 짝지은 별 / quad에 쓴 별 4개 / 식별에 쓴 별(데모 범례) / 후보의 출발점 / 짝에 쓰지 않은 별(배운 것). 마지막 교훈이 앞 장 데모 말("식별")과 이어지지 않는다 → 한 단어로(예: "맞춘 별").
- **지문 / 모양 값 / quad 값**: quad는 "지문", 삼각형은 "모양 값", quad-hash 데모 ③은 "quad 값 = … = 지문" → "지문"으로 통일하거나 삼각형 장 노트에 "삼각형의 지문 = 모양 값".
- **별 등급**: "3.5등급만 = 밝은 별"인데 숫자가 작을수록 밝다는 설명이 한참 뒤(L1362) → 첫 등장(L938)에 한 줄.
- **원근 보정 vs 원근 변환**: 사진 편집(건물 세우기)과 수학 모델(사다리꼴)이 한 줄에 같이 나온다(L756 "원근 보정한 사진은 원근 변환으로") → "건물을 똑바로 세운 사진 → 사다리꼴까지 맞추는 변환으로".
- **RANSAC**: 화면 "겹친 별 여러 쌍으로 다시 맞추기 (RANSAC)"는 ②(전부로 맞추기)와 구별 안 됨 → "몇 쌍씩 무작위로 맞춰 보고 가장 많은 별이 동의하는 것 고르기".
- **별다움**: 정의(별다움 장)보다 앞 장(사람을 흉내 내자) 질문 대비 노트에 먼저 나온다.
- **모델**: 오차 보정 장에서 정의 없이 등장, 앞에서는 "변환" → 통일하거나 "변환 방식(모델)".
- **별 목록 이름**: 별 지도 / 별 목록 / 카탈로그 / quad DB / 패턴 DB / 색인(SkySphere 데모) → 별 지도와 quad DB 둘로.
- **Plate Solver 표기**: 영어와 "플레이트 솔버"가 섞임(2022 목표 장 한 줄 안에 둘 다).
- 무거운 말: "별의 배치를 식별하려면?" → "별 배치를 알아보려면?", "회전, 크기, 이동에 강건한 지문" → "돌려도 키워도 옮겨도 그대로인 지문", "서로 보완재" → 빼기, "광해" → "도시 불빛 번짐", "기각" → "버리기", refine 데모 ④ "광축에서의 각도에 비례해…" → "가운데서 멀수록 더 눌러 담는 어안 렌즈".

## 5. 기술

- **깨진 링크 없음**: 주소 75개(그림 41, 썸네일 16, 데모 13, 페이지 4, 데이터 7) 모두 200. 태그 짝·중첩·id 문제 없음.
- **오버레이 h1**(OpenCV를 쓰지 말자, 편의성은 직접 판단해 보세요, AI는 저보다…)이 제목용 h1 스타일(높이 11.8%, 왼쪽 정렬)을 물려받을 수 있다 — 지금 화면에서는 가운데로 보였지만 크기는 제목과 같다. 오버레이용 클래스를 따로 두면 안전.
- **긴 제목 두 줄 위험**(한 줄 약 26자): "가짜 삼각형 줄이기: 화각을 짐작하면 크기로 거를 수 있다"(31자), "버즈빌은 해외로…", "삼각형과 quad는 서로 보완재: 둘 다 쓰자", "멀어질수록 늘어나는 오차를 어떻게 보정할까?".
- **iframe 16개가 덱을 열자마자 다 뜬다**: /plate-solver는 풀이 Worker를 미리 만들고(메모리 수백 MB), sky-sphere는 Three.js. 발표 노트북이 처음에 버벅일 수 있다. `data-src`로 바꾸면 근처에서만 불러오지만 멀리 넘기면 데모 상태가 초기화된다.
- **데모를 클릭하면 키 입력이 iframe으로 간다**: 클리커·→가 안 먹고 바깥을 한 번 눌러야 한다. 리허설 때 확인하거나 embed에서 키를 덱으로 넘기는 코드 추가.
- 사이판 장 글 칸(left 70% 절대 위치)이 그림 비율에 따라 겹칠 수 있다 — 실제 화면 확인.
- 저작권: 외부 카페 사진은 들어가지 않았다(데모는 숫자만). 새 동료 사진·Slack 화면 없음. 그대로 두기로 한 것: 사이판 Slack 계열(이번에 time·place 그림 2장 추가), 노을 사진, 구글 썸네일. cafe-orion 썸네일 출처는 확인 권함(docs/ux-review.md:21).
